# Development History — BSAPS  
(Battery Stress Assessment & Protection System)

본 문서는 BSAPS 프로젝트의 개발 과정을 사후 회고 방식으로 정리한 기록이다.  
이 프로젝트의 핵심 목적은 배터리의 SOH(열화 상태)를 정밀 추정하는 것이 아니라,  
배터리 수명을 빠르게 악화시키는 사용 스트레스 환경을 판단하고  
임계 상황에서 보호(PROTECT) 동작까지 수행하는 시스템을 구현하는 것이다.

---

## 1. Project Overview

- Project Name: BSAPS (Battery Stress Assessment & Protection System)
- Target Platform: ESP32 (v1, pre-STM32)
- Design Approach:
  - 상태머신 기반 시스템 설계
  - 하드웨어 물리 특성과 시간 흐름 중심 판단
  - 보호 동작을 포함한 실사용 관점의 임베디드 시스템

본 프로젝트는 정확한 진단보다 거칠게 사용되는 환경의 감지와 즉각적 보호에 초점을 둔다.

---

## 2. Hardware 구성 및 실험 환경

### 2.1 사용 부품

- ESP32 Dev Module (ESP32-WROOM-32 계열)
- DS18B20 온도 센서
- INA219 전류 센서 모듈
- 아두이노 전압 측정 센서 모듈
- 저항
  - 4.7kΩ (1/4W) — 신호용
  - 330Ω (1W) — 부하용
  - 100Ω 3W 5% Axial — 고부하 실험용
- 스위치 (AT1D-2M3)
- 전원
  - 12V 2A 어댑터
  - DC 터미널 변환 젠더
  - USB 케이블

### 2.2 전원 및 테스트 방식

- 현재 테스트는 실제 배터리가 아닌 12V 어댑터 기반
- 버튼 입력으로 MOSFET을 ON 하여 부하를 인가
- 전류 스트레스를 의도적으로 발생시키는 실험 구조
- 상태머신이 스트레스를 감지하면 자동으로 부하 차단

---

## 3. 설계 원칙과 개발 방식

### 3.1 목적 고정 원칙

개발 과정에서 다음 항목은 의도적으로 배제하였다.

- 배터리 SOH 추정
- 복잡한 모델링
- 머신러닝 기반 예측

대신 다음 항목에 집중하였다.

- 사용 스트레스 환경 판단
- 상태머신 기반 보호 동작
- 실제 하드웨어에서 검증 가능한 구조

### 3.2 Baseline 중심 개발

디버깅 과정에서 기능이 비대해지고 원인이 흐려지는 문제를 경험하였다.  
이를 계기로 정상 동작 기준점을 먼저 고정한 뒤 확장하는 개발 방식을 채택하였다.

---

## 4. 상태머신 설계

### 4.1 정의된 상태

- IDLE
- LOAD_ON
- STRESS
- PROTECT
- COOLING
- IDLE 복귀

### 4.2 Baseline A1 동작 흐름

- 버튼을 약 10초간 누르면 상태가 순차적으로 전이됨  
  IDLE → LOAD_ON → STRESS → PROTECT → COOLING → IDLE
- 해당 흐름에서 MOSFET 제어, 전류 측정, 자동 차단, 로그 출력이 모두 정상 동작함을 확인한 시점을 Baseline A1으로 정의함

---

## 5. 센서 연동 및 판단 로직

### 5.1 온도 센서

- 온도는 판단 보조 지표로 사용
- 센서 갱신 주기 1초
- 로그 출력 주기 500ms
- 갱신 사이에는 최근 값 유지 방식 적용

### 5.2 전압 센서 및 ADC 문제

- ADC 입력이 불안정하게 변동하는 현상 발생
- 원인은 입력 floating과 배선 영향으로 판단
- 하드웨어 풀다운과 소프트웨어 안정화 처리로 해결
- 전압 센서와 온도 센서를 동시에 안정적으로 측정 가능

### 5.3 전류 센서

- 전류를 스트레스 판단의 핵심 지표로 사용
- 부하 인가 시 전류 상승 감지
- 임계 조건 도달 시 보호 상태로 전환하여 MOSFET 차단

---

## 6. 보호 동작 설계

- 보호 동작은 코드 기반으로 구현
- 추가 하드웨어 없이 자동 차단 수행
- 보호 이후 냉각 단계를 거쳐 정상 상태로 복귀

---

## 7. 주요 디버깅 경험

### 7.1 ADC Floating 문제

- 전압 값이 불안정하게 출력되는 문제 경험
- 하드웨어와 소프트웨어 경계에 대한 이해가 필요함을 인식
- 센서 안정성 설계의 중요성을 체득

### 7.2 무한 디버깅 루프 경험

- 문제 해결 과정에서 기능이 과도하게 늘어나는 상황 경험
- 목적과 기준선이 없으면 디버깅이 실패함을 체감
- 이후 목적 고정과 baseline 중심 개발 원칙 확립

## 10. 정리

본 프로젝트는 센서 연동 실습을 넘어  
환경, 상태, 판단, 보호로 이어지는 임베디드 시스템 사고 과정을 정리한 결과물이다.  
Baseline과 상태머신 설계는 이후 프로젝트에도 그대로 적용 가능한 핵심 경험이다.
